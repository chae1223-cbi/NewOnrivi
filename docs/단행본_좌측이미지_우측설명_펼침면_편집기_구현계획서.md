# 단행본 왼쪽 이미지·오른쪽 설명 펼침면 편집기 구현 계획서

작성일: 2026-11-19 · 상태: 구현 전 계획

## 1. 목표

온리비어서에서 단행본을 펼친 모습으로 편집한다. 한 장면은 **왼쪽 한 페이지에 이미지**, **오른쪽 한 페이지에 설명 글**을 배치한다. 화면에서는 두 페이지를 나란히 보여주고, PDF와 인쇄에는 각 페이지를 독립된 실제 종이 한 쪽으로 내보낸다. 이미지 교체와 설명 글 수정은 펼침면에서 바로 할 수 있어야 한다.

```text
화면 편집                         PDF·인쇄 페이지 순서
┌──────────────┬──────────────┐    2쪽: 이미지  →  3쪽: 설명
│ 왼쪽: 이미지   │ 오른쪽: 설명   │    4쪽: 이미지  →  5쪽: 설명
└──────────────┴──────────────┘
```

## 2. 현재 구조와 활용할 부분

- `frontend/src/lib/picturebook.ts`의 `:::scene` 문법은 이미지와 설명 본문을 한 장면으로 보관한다. 장면 파싱·교체·순서 이동 기능을 재사용한다.
- `frontend/src/components/PicturebookPreview.tsx`는 그림책·사진앨범을 고정 크기 페이지로 보여주고 이미지 교체·본문 직접 편집·본문 넘침 감지를 수행한다. 현재는 이미지와 글을 **한 페이지 내부의 두 열**로 배치한다.
- `frontend/src/types/cssProfile.ts`의 `layout.type = 'picturebook'`과 서식 프로필은 용지, 여백, 글꼴, 이미지 맞춤을 제공한다. 새 배치 방식은 기존 프로필에 영향을 주지 않는 구분 값 또는 별도 타입으로 추가한다.
- `frontend/src/lib/export/pdfExporter.ts`는 그림책의 `.book-page`를 실제 용지 크기로 한 쪽씩 출력한다. 펼침면 표시용 바깥 컨테이너와 인쇄용 각 페이지를 분리하면 활용할 수 있다.
- `frontend/src/lib/picturebookEpub.ts`는 고정 레이아웃 EPUB으로 내보낸다. 좌우 페이지 메타데이터 및 독서기 호환성은 별도 검증이 필요하다.

**핵심 차이:** 기존 그림책의 2열 페이지 폭을 절반씩 나누는 방식으로는 이 요구를 충족하지 않는다. 각 장면이 동일 판형의 독립된 **두 물리 페이지**를 생성해야 한다.

## 3. 범위와 기본 결정

| 항목 | 첫 구현의 기준 |
| --- | --- |
| 편집 모드 | 기존 그림책과 구분되는 `이미지·설명 펼침면` 배치 옵션 |
| 문서 원본 | 기존 `:::scene`의 이미지 1개와 설명 본문을 유지; 새 문법 강제 없음 |
| 장면당 페이지 | 이미지 왼쪽 1쪽 + 설명 오른쪽 1쪽 |
| 용지 | 한 페이지의 판형을 서식 프로필에서 가져옴; 펼침면은 두 페이지의 화면 배치 |
| 이미지 | 한 페이지 안에서 `contain`/`cover` 선택 및 초점 위치 조정 검토 |
| 글 | 오른쪽 페이지에서 직접 편집; 기존 문단·제목 등 마크다운 서식 보존 |
| 넘침 | 첫 구현에서는 넘침 경고와 내보내기 차단; 사용자가 장면을 나눠 해결 |
| 출력 | PDF·인쇄에서 한 쪽당 한 페이지, 홀짝 순서 검증 |
| EPUB | PDF·인쇄 안정화 뒤 고정 레이아웃 펼침면 지원 |
| DOCX·HWPX | 첫 구현 범위에서 제외; 기존 그림책 제한과 충돌 없게 표시 |

표지와 앞부분의 페이지 수에 따라 첫 이미지 페이지가 왼쪽에 오도록 정렬한다. 일반적인 단행본에서는 오른쪽 페이지가 홀수, 왼쪽 페이지가 짝수다. 표지가 1쪽이면 첫 이미지는 2쪽, 첫 설명은 3쪽이다. 표지가 없다면 시작 정렬용 빈 오른쪽 페이지를 명시적으로 추가하거나 첫 장면의 시작 방식을 선택하게 한다. 빈 페이지를 **화면에서 숨긴 채 출력에만 몰래 넣지 않는다.**

## 4. 문서와 배치 데이터

### 4.1 기존 문서 호환

장면 원문은 다음 구조를 유지한다.

```markdown
:::scene
![이미지 설명](<images/example.jpg>)

## 장면 제목
오른쪽 페이지에 표시할 설명 글.
:::
```

새 배치 모드는 문서의 내용 자체보다 **서식 프로필의 배치 설정**으로 결정한다. 기존 `picturebook` 프로필과 문서를 열면 기존 한 페이지 2열 동작을 그대로 유지한다. 새 모드에서 저장한 문서를 일반 마크다운으로 열어도 이미지와 설명 원문은 읽을 수 있어야 한다. 배치 설정을 끈 뒤에도 장면 내용은 삭제하지 않는다.

### 4.2 렌더링 모델

`BookScene`을 화면에 직접 한 페이지로 그리는 방식에서, 파싱 결과로부터 다음 출력 모델을 만든다.

```text
Scene 1 -> image page 2, text page 3
Scene 2 -> image page 4, text page 5
...
```

각 출력 페이지에는 장면 ID, 이미지/글 역할, 물리 페이지 번호, 원문 줄 범위가 필요하다. 페이지 묶음은 화면용이며 PDF·인쇄의 용지 크기가 되지 않는다. 페이지 번호는 화면, PDF, 인쇄에 같은 계산 결과를 사용한다. 표지·앞부분·명시적 빈 페이지가 있으면 같은 페이지 모델에서 계산한다.

### 4.3 변경 버전

기존 `layout.schemaVersion`과 파서가 허용하는 형식을 확인한 뒤 새 배치 값을 버전 관리한다. 지원하지 않는 배치 버전을 만나면 임의로 기존 그림책 모드로 표시하지 않고 명확히 알려준다. 기존 사용자 프로필의 마이그레이션은 배치 속성의 기본값만 추가하는 방식으로 설계한다.

## 5. 편집 화면

1. 서식 설정에서 `이미지·설명 펼침면`을 선택한다. 한 페이지의 판형·방향·여백과 이미지 맞춤 방식은 서식에서 조정한다.
2. 장면 추가 시 이미지 영역과 글 영역이 한 쌍으로 생성된다. 왼쪽 이미지 영역에서는 드롭·붙여넣기·파일 선택으로 이미지를 넣거나 교체한다.
3. 오른쪽 설명 영역은 기존 VisualDocumentEditor를 재사용해 문단, 인용문, 목록, 제목 등을 편집한다. 변경은 해당 `:::scene` 본문에만 반영한다.
4. 페이지 사이 중앙에는 제본 경계가 보이게 하고, 바깥쪽/안쪽 여백을 구분한다. 화면 확대·축소는 두 페이지를 함께 조정하며 저장 내용이나 실제 출력 크기를 바꾸지 않는다.
5. 장면 목록에서는 `장면 1 (2–3쪽)`처럼 펼침면과 실제 페이지 번호를 표시한다. 장면 이동·복제·삭제는 이미지와 글을 항상 한 쌍으로 처리한다.
6. 설명 글이 페이지를 넘으면 넘친 위치를 표시한다. 첫 구현에서는 자동으로 다음 장면의 왼쪽 이미지를 밀거나 새 빈 페이지를 만들지 않는다. 사용자가 글을 줄이거나 새 장면으로 나눈 뒤 내보낼 수 있다.

## 6. 조판·인쇄 규칙

### 6.1 한 쪽의 치수

서식 프로필의 `paperSize`와 방향이 **한 페이지의 크기**다. 화면 펼침면 폭은 두 페이지 폭과 중앙 제본 간격의 합이다. PDF의 `@page`는 펼침면 폭이 아닌 한 페이지 크기로 설정한다. A4뿐 아니라 신국판·B5 등 현재 지원 판형에서 동일한 규칙을 적용한다.

### 6.2 좌우와 제본 여백

- 짝수 페이지는 왼쪽, 홀수 페이지는 오른쪽에 배치한다.
- 왼쪽 이미지와 오른쪽 글은 서로 다른 물리 페이지다. 양쪽 페이지의 안쪽 여백은 제본 쪽을 향한다.
- 화면의 중앙 그림자·경계·조작 버튼은 출력물에 포함하지 않는다.
- 여백 없는 이미지를 요구할 경우 재단 여유(bleed), 안전 영역, 프린터 인쇄 가능 영역을 별도 인쇄 옵션으로 다룬다. 첫 구현에서 실제 무테 출력을 보장한다고 표시하지 않는다.
- 이미지의 원본 픽셀과 배치 크기를 비교해 저해상도 경고를 표시할 수 있다. 확대 인쇄로 품질이 저하되는 것을 숨기지 않는다.

### 6.3 페이지 순서와 출력

PDF는 `표지 → 필요 시 앞부분/빈 쪽 → 이미지 → 설명 → 이미지 → 설명`의 한 페이지씩 순서로 생성한다. 양면 인쇄에서는 해당 PDF를 두 쪽 모아 인쇄하도록 강제하지 않고, 프린터의 양면 설정과 긴 쪽 넘김을 사용한다. 단면 인쇄에도 페이지 순서가 같아야 한다.

페이지 번호 표시 여부는 기존 프로필 설정을 따른다. 표지·빈 페이지 번호를 표시할지 여부는 별도로 구분하되 물리 페이지 순서에는 포함한다. PDF 생성 결과에서 실제 페이지 수, 페이지 치수, 좌우 순서를 검증한다.

## 7. 내보내기 경로

### PDF·인쇄: 첫 출시 범위

`PicturebookPreview`가 생성한 각 물리 페이지에 `.book-page`를 유지하고, 화면에서만 두 페이지를 `.book-spread`로 묶는다. PDF 생성 단계에서는 펼침면 묶음의 flex/grid 배치를 해제하고 `.book-page`를 순서대로 한 쪽씩 출력한다. 기존 PDF exporter의 그림책용 `@page`와 한 쪽 치수를 재사용하되, 빈 쪽·표지·홀짝 페이지와 설명 넘침 검사를 추가한다.

### EPUB: 후속 범위

기존 고정 레이아웃 EPUB은 `.book-page`를 각각 한 섹션으로 만든다. 새 모드에서는 각 페이지를 독립된 고정 레이아웃 XHTML로 유지하고, 읽기 앱이 왼쪽·오른쪽을 함께 표시할 수 있도록 페이지 진행 방향과 펼침면 힌트를 검증한다. 일부 EPUB 독서기는 두 페이지를 한 화면에 보여주지 않을 수 있으므로, 첫 출시의 보장 범위에는 포함하지 않는다.

### 기타 내보내기

페이지 이미지 내보내기는 실제 한 쪽 단위와 펼침면 미리보기 단위를 혼동하지 않도록 별도 옵션으로 다룬다. DOCX·HWPX는 기존 그림책처럼 첫 출시 범위에서 제외하고, 선택 불가능한 형식을 명확히 표시한다.

## 8. 구현 단계

### 1단계 — 배치 모델과 호환성

- 새 배치 선택값 및 설정 버전을 정의한다.
- 기존 `:::scene` 원문에서 이미지 페이지와 설명 페이지를 생성하는 순수 페이지 모델을 만든다.
- 기존 그림책·사진앨범 모드의 출력이 변하지 않는지 확인한다.
- 표지, 빈 쪽, 장면 이동에 따른 페이지 번호를 한 곳에서 계산한다.

**완료 기준:** 같은 장면 문서를 기존 모드와 새 모드로 각각 열어도 원문 손실 없이 서로 다른 배치가 나온다.

### 2단계 — 펼침면 편집 UI

- 왼쪽 이미지·오른쪽 글을 두 개의 실제 페이지로 표시한다.
- 이미지 교체와 글 직접 편집, 장면 추가·이동·복제를 연결한다.
- 제본 경계·페이지 번호·확대·축소·반응형 화면을 구성한다.
- 설명 넘침과 이미지 누락을 장면별로 표시한다.

**완료 기준:** 사용자가 한 장면의 이미지와 설명을 화면에서 수정하고 저장·재열기 후 동일한 내용과 페이지 배치를 본다.

### 3단계 — PDF·인쇄

- 화면 묶음을 해제해 한 `.book-page`당 한 PDF 페이지로 출력한다.
- 적용된 판형과 방향, 표지와 빈 쪽, 양면 인쇄용 홀짝 순서를 검증한다.
- 넘침·이미지 누락 시 내보내기를 중단하고 해당 장면을 찾을 수 있게 한다.

**완료 기준:** 표지 1쪽 + 두 장면 4쪽은 총 5쪽 PDF가 되고, 첫 이미지가 2쪽 왼쪽, 첫 설명이 3쪽 오른쪽에 놓인다. 실제 PDF 용지 크기는 펼침면이 아닌 서식에 지정한 한 페이지 크기다.

### 4단계 — EPUB·페이지 이미지 및 편집 경험 개선

- 고정 레이아웃 EPUB의 좌우 페이지 표시를 독서기별로 검증한다.
- 선택적 펼침면 이미지 내보내기와 저해상도 경고를 추가한다.
- 필요하면 설명 이어쓰기 정책을 별도 설계한다.

**완료 기준:** 지원하는 내보내기 형식마다 좌우 페이지 순서와 치수를 명시하고 실제 파일로 확인한다.

## 9. 핵심 검증 시나리오

1. 표지 1쪽과 장면 2개를 만들면 화면에서 두 펼침면, PDF에서 5개의 한 쪽 페이지가 나온다.
2. 표지가 없는 문서는 첫 이미지가 왼쪽에 오도록 빈 오른쪽 시작 페이지를 명시적으로 표시하거나 사용자가 시작 방식을 선택한다.
3. 장면 순서를 바꾸면 이미지·설명 쌍이 함께 이동하고 페이지 번호가 다시 계산된다.
4. 이미지 없이 저장된 장면, 로딩 실패 이미지, 설명 넘침은 편집 화면과 내보내기 전에 발견된다.
5. 오른쪽 설명에 제목·인용문·목록·링크가 있어도 수정·저장·재열기 뒤 마크다운 원문이 유지된다.
6. A4, B5, 신국판 등 서로 다른 판형에서 화면과 PDF의 **한 쪽 치수**가 일치한다.
7. 양면 인쇄의 홀짝 순서를 확인하고, 프린터가 실제로 출력한 시험본에서 왼쪽 이미지·오른쪽 글이 마주 보는지 확인한다.
8. 기존 그림책·사진앨범 문서를 열고 PDF로 내보낼 때 기존 한 페이지 2열 배치가 변하지 않는다.

| 항목 | 권장 기본값 | 선택이 필요한 이유 |
| --- | --- | --- |
| 표지 없는 문서의 시작 | 앞에 빈 오른쪽 페이지를 화면·출력 모두에 표시 | 첫 이미지가 왼쪽 짝수 쪽이어야 함 |
| 이미지 크롭 | 기본 `contain`, 필요할 때 `cover` | 그림의 잘림 방지와 페이지 채움 중 선택 |
| 설명 넘침 | 내보내기 차단 후 사용자가 장면 분할 | 자동 이어쓰기 시 이미지·글의 좌우 짝이 깨질 수 있음 |
| 제본 여백 | 기존 여백에 안쪽 여백 옵션 추가 | 실제 단행본은 안쪽이 더 넓어야 할 수 있음 |
| 표지 형식 | 기존 그림책 표지 재사용 | 표지는 펼침면 장면과 다른 단일 페이지 |
| EPUB 지원 | PDF 출시 후 별도 검증 | 독서기마다 펼침면 표시가 다름 |

## 11. 결론

현 그림책 기능을 재사용하되, **한 장면을 한 페이지에 두 열로 그리는 로직**과 **한 장면을 두 물리 페이지로 펼치는 로직**은 분리한다. 첫 출시는 편집 화면과 PDF·인쇄가 동일한 페이지 모델을 공유하고, 설명 넘침을 명확히 처리하는 데 집중한다. EPUB과 자동 이어쓰기는 좌우 짝이 깨지지 않는 규칙을 검증한 뒤 확장한다.
