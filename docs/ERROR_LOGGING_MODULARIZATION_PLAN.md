# 온리비 어서 오류 진단 및 대형 소스 분리 실행 계획

작성일: 2026-11-03  
적용 저장소: `D:\Developer\NewOnrivi`

## 1. 목표와 범위

- 파일 읽기·저장, 세션 복원, 인증, 서버 API 실패 시 **어떤 작업(`doing`)을 어떤 대상(`target`)에 수행했는지** 추적한다.
- 기존 `frontend/src/lib/errorDiagnostics.ts`와 `functions/api/_server-error.js`를 공통 진입점으로 사용한다.
- 사용자에게 보이는 메시지, API 응답 계약, 인증 흐름, DB 처리 방식은 로깅 작업만으로 바꾸지 않는다.
- 대형 파일은 기능 단위로 분리하며 기존 import 경로와 동작을 유지한다. 줄 수 자체는 완료 기준으로 삼지 않는다.

## 2. 착수 전 확인

1. `AGENTS.md`, `.agents/AGENTS.md`와 변경 범위에 맞는 `skills/onrivi-*.md`가 아닌 `skills/*/SKILL.md`를 읽는다. 소스 주석·오류 처리 지침은 모든 코드 변경에 적용한다. DB·공통 코드·메시지 변경이 필요하면 해당 스킬도 적용한다.
2. 기존 로거의 실제 수집 경로, 마스킹 범위, 실패 시 동작, 30일 보관 설정을 확인한다. **로거 자체의 실패가 저장·로그인 같은 원래 작업을 실패시키지 않아야 한다.**
3. 운영·로컬의 소스맵 제공 여부를 확인한다. 스택의 파일·줄 번호는 번들/소스맵에 따라 달라질 수 있으므로 `file`, `func`, `doing`, 요청 ID를 우선 신뢰한다.
4. 현재 기준선을 기록한다: 타입 검사, 정적 빌드, 대표 사용자 시나리오(Drive 연결·파일 열기·저장·세션 복원·로그인)의 결과. 기존 실패는 신규 회귀와 구분한다.

## 3. 공통 로그 계약

| 필드 | 규칙 |
| --- | --- |
| `file`, `func` | 호출부의 저장소 상대 경로와 함수명. 자동 스택 추출은 보조 수단. |
| `doing` | 실패 직전 수행한 구체적 작업 단계. 광범위한 함수명 반복 금지. |
| `target` | 문제를 재현할 최소 식별자. 가능하면 내부 ID의 일부 또는 비식별 값. |
| `error` | 원본 예외를 공통 로거에 전달. 외부 전송 전 민감정보 제거. |
| `requestId` | 서버 요청의 오류 응답과 구조화 로그를 연결. |

- 토큰, 비밀번호, 쿠키, Authorization 헤더, DB URL, 문서 본문, 이메일 원문, 전체 로컬 경로를 기록하지 않는다. `error.message`와 `stack`에도 민감정보가 섞일 수 있으므로 **필드명 기반 마스킹만으로 충분하다고 가정하지 않는다.**
- 사용자 알림 또는 오류 응답 전 로그를 남긴다. 예상 가능한 4xx도 지침대로 기록하되, 반복량과 중요도를 구분하고 원인·라우트·요청 ID만 남긴다.
- 오류 로깅은 진단 목적이며 사용자에게 새 메시지나 코드를 추가할 때는 해당 스킬의 승인 절차를 따른다.

## 4. 실행 순서

### 0단계 — 로거 안전성 점검

대상: `frontend/src/lib/errorDiagnostics.ts`, `frontend/src/lib/clientLogs.ts`, `functions/api/_server-error.js` 및 로그 수집 설정.

- `target`, `context`, `error.message`, `stack`의 마스킹과 크기 제한을 점검한다.
- 클라이언트 로그 전송 실패가 원래 작업의 예외 흐름을 바꾸지 않는지 확인한다.
- R2 `_system-logs/` 수명 주기 30일 규칙은 설정과 실제 저장 경로를 각각 확인한다. 계획서에 존재한다는 사실만으로 적용되었다고 간주하지 않는다.
- 완료 기준: 민감정보 샘플이 콘솔/전송 페이로드에 남지 않고, 로그 수집 실패 시 원래 작업 결과가 유지된다.

### 1단계 — Google Drive·로컬 파일 I/O

대상: `frontend/src/hooks/useFileExplorer.ts`, `frontend/src/lib/gdrive/googleDriveClient.ts`.

1. `connectGoogleDrive`: 토큰 **값**은 남기지 않고 토큰 확인·계정 조회·작업장 폴더 조회·목록 조회 단계만 기록한다.
2. `handleFileClick`, `readDriveFileContent`: 파일 읽기 실패 지점과 비식별 대상 ID를 기록한다.
3. `saveFile` 및 로컬 VFS 쓰기: Drive 업로드·Electron 파일 쓰기·브라우저 VFS 쓰기를 구분한다. 저장 실패 후 성공으로 오인하거나 기존 내용을 덮어쓰지 않는지 확인한다.
4. 기존 `console.error`/`warn`과 공통 로거가 같은 실패를 중복 전송하지 않도록 호출 경계를 정한다.

완료 기준: Drive 연결·해제, 파일 열기, 새 파일 저장, 기존 파일 저장, 실패 후 재시도에서 기능과 알림이 유지되고 실패 단계가 로그에서 구분된다.

### 2단계 — 에디터 세션·자동 저장

대상: `frontend/src/components/MainEditorApp.tsx`, `frontend/src/hooks/useEditorHandlers.ts` 및 실제 세션 저장 소유 모듈.

- 세션 저장·복원 코드를 검색해 실제 소유 함수를 확정한 뒤 `localStorage` 읽기/파싱, 탭별 복원, Monaco 모델 연결, 직렬화/자동 저장의 실패 지점에 기록한다.
- 탭 제목·문서 내용 대신 탭 수, 탭 유형, 비식별 탭 ID와 실패 단계만 기록한다.
- 복원 실패 시 기존 복구 정책을 유지한다. 새 폴백이나 빈 내용 덮어쓰기를 도입하지 않는다.

완료 기준: 정상 재시작 시 탭·내용이 유지되고, 손상된 세션 1건이 다른 탭의 복원을 막지 않는지 현재 정책에 맞게 확인한다.

### 3단계 — 로그인·기기 라이선스

대상: `frontend/src/app/login/page.tsx`, `frontend/src/app/dashboard/page.tsx`, 실제 라이선스 호출 모듈.

- 인증, `/api/license/activate`, `/api/subscription/get`의 네트워크 실패·HTTP 실패·응답 파싱 실패를 구분한다.
- 이메일·토큰·세션 비밀값은 로그에서 제외한다. 세션 ID도 공개 가능한 내부 식별자인지 확인 후 기록한다.
- 기존 로그인 분기와 사용자 메시지를 유지한다.

완료 기준: 정상 로그인·로그아웃·재로그인과 대표 실패 응답에서 기존 동작이 유지되고 로그의 단계가 구분된다.

### 4단계 — 서버 API

대상: `functions/api/subscription/**`, `functions/api/device/**`, `functions/api/gdrive/**`의 실제 라우트.

- 실패를 반환하는 경로를 목록화한 뒤 `serverError(request, error, {source, stage, doing, target})`를 적용한다.
- 예상 가능한 400/401/403/404는 응답 직전 요청 ID·라우트·사유를 구조화 기록한다. 정상적인 반복 요청이 로그를 과도하게 채우지 않는지 확인한다.
- `requestId`가 응답과 로그에서 일치하고, 내부 SQL/스택이 응답에 노출되지 않는지 확인한다.
- DB 트랜잭션 코드를 만지는 경우 DB 처리 스킬을 먼저 적용하고 원자성·롤백을 별도 검증한다.

완료 기준: 각 라우트의 정상 응답 계약이 유지되고 예외 응답은 동일 요청 ID로 추적된다.

## 6. 변경 단위와 검증 게이트

- 한 변경 단위는 한 도메인 또는 한 기능 추출로 제한한다. 파일별 `@PATCH` 이력을 남기고 필요하면 해당 단위로 커밋한다.
- 매 단위: `npm run typecheck --prefix frontend`; 변경이 정적 배포·Electron 출력에 영향을 주면 해당 빌드도 수행한다.
- 런타임 확인: 웹 localhost와 해당 기능이 쓰이는 Electron/Cloudflare 경로를 구분하여 확인한다. 로컬 성공만으로 배포 성공을 선언하지 않는다.
- 실패 시 중단: 타입 오류, 정상 저장/복원 회귀, 로그 민감정보 노출, 응답 계약 변경, DB 원자성 손상. 해당 단위만 되돌릴 수 있도록 변경을 작게 유지한다.
- 최종 산출물: 적용 파일 목록, 실패 경로별 `doing` 목록, 마스킹 검증 결과, 검증 명령과 결과, 남은 위험.
